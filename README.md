# student_auto_aim —— RoboMaster 视觉组二轮考核自瞄节点

基于 ROS 2 的自动瞄准程序，配合 RoboMaster Aim Lab 仿真平台使用。
程序订阅仿真给出的可见装甲四角坐标，完成 **目标装甲选择 → 空间几何解算 → 重力补偿 → 运动预测 → 到位开火** 全流程，不依赖仿真任何内部真值，也不使用内置辅助瞄准。

## 2. 依赖与编译

依赖：ROS 2 Jazzy、`rclcpp`、`std_msgs`、`geometry_msgs`、`rm_aim_sim_bridge`（仿真仓库自带）。

```bash
# 1. 仿真仓库先编译好桥接（只需一次）
cd ~/rm_aim_sim_training
source /opt/ros/jazzy/setup.bash
cd ros2_ws && colcon build --packages-select rm_aim_sim_bridge && cd ..

# 2. 编译本功能包
mkdir -p ~/student_ws/src

cd ~/student_ws
source /opt/ros/jazzy/setup.bash
source ~/rm_aim_sim_training/ros2_ws/install/setup.bash
colcon build --packages-select student_auto_aim
source install/setup.bash
```

> 每次修改 `.msg` 或桥接源码后，桥接与本包都要重新编译。

```bash

source ~/rm_aim_sim_training/ros2_ws/install/setup.bash
source ~/student_ws/install/setup.bash
ros2 run student_auto_aim aim_node --ros-args -p use_sim_time:=true
```

> `use_sim_time:=true` 必须开。节点靠 `/clock` 计算观测年龄，不开会导致时间基准错乱（节点会打警告并按固定延迟补偿）。

联调第一步：把 `fire` 相关逻辑临时验证时，可先只看 `ros2 topic echo /aim_sim/command`，确认 `yaw` 符号（目标在左侧时为正）与 `pitch` 符号（抬头为正）正确。

## 4. 通信接口

| 方向 | 话题 | 类型 | 用途 |
|---|---|---|---|
| 订阅 | `/aim_sim/armors` | `ArmorCornersArray` | 可见装甲四角（odom，米） |
| 订阅 | `/aim_sim/gimbal` | `GimbalState` | 实际 yaw/pitch 及角速度 |
| 订阅 | `/aim_sim/telemetry` | `Telemetry` | 弹速、重力、枪管长度、射速、开火延迟 |
| 发布 | `/aim_sim/command` | `AimCommand` | 目标角 + enable + fire |

QoS 统一 `reliable / volatile / depth = 1`；指令以 50 Hz 发布，且 `header`、`session_id` 一律复制当次计算所用观测，不修改时间戳。

## 5. 程序结构与算法

### 5.1 单帧处理流水线（`controlLoop`，50 Hz）

1. **置位检查**：未收到 gimbal/armors 直接返回。
2. **空列表处理**：按手册要求，收到空列表就发 `enable=false / fire=false`（使用这条空观测自己的 header 与 session_id）；但**不清空运动历史**——命中后装甲灭灯 50 ms、侧对出画都属于短暂丢失，下一帧回来时可以直接沿用已有的速度估计，不必从头攒样本。
3. **会话与时效**：`session_id` 变化立即清空跟踪状态；观测年龄 > 250 ms 时停控，避免发旧结果。
4. **装甲几何**：每块板取四角均值作为命中矩形中心，`n = normalize((p2-p1) × (p1-p0))` 为朝外法向（注意是"下×右"，反过来会指向机器人内部），`facing = n · normalize(muzzle - center)` 衡量正对程度。
5. **目标选择（按法向锁板）**：两步走。第一步"锁板"——把上一帧的法向按 `ω·Δt` 前推，然后在 `facing ≥ facing_hold`（0.4）的板里找法向夹角小于 20° 且位置相差小于 `3 × plate_jump_gate` 的那块，继续打它；第二步"重新捕获"——锁不到时才按 `score = facing - 0.06·距离 - 0.15·偏航角` 在所有 `facing ≥ facing_min`（0.5）的板里选最优。
   用**法向**而不是位置来锁板，是因为同一台机器人的几块板方位差 90°、高度与半径也不完全相同（仿真里 `height_difference = -0.1`，实测两块板 x 差 0.25 m、z 差 0.10 m）。位置相近无法区分"同一块板"和"另一块高度略有不同的板"，而法向是每块板唯一的，且旋转时只按 `ω` 缓慢变化。
   门槛为什么定这么高：仿真命中判定用板自身 `tangent/up` 做矩形（半宽 0.0675 m），正对时可容 6.75 cm 横向偏差；而**侧对板**（法向与弹道近乎垂直）的横向偏差会被放大成沿板面位移，等效容差只有约 `0.0675 × facing ≈ 1.3 cm`，实际打不中。平移场景里侧对板的 `facing` 峰值只有 0.225，所以门槛取 0.5 能彻底排除它；旋转场景四板 90° 分布，任一时刻最优板的 `facing ≥ 0.707`，0.5 的门槛不会影响持续开火。
   **旋转靶要按"到场正对"选板**（`|omega| > omega_deadband` 时走这条分支）：命中面随板一起转，`ω × 飞行时间` 在 ω=4 rad/s、6 m 时约 1.24 rad（71°）。按"此刻正对"选板，子弹飞到的时候那块板已经转成 71° 斜擦，等效容差只剩两三厘米，实测 30 发里 11 发穿透飞过（`expired`）。所以旋转靶改成把每块板的法向按 `ω·lead` 前推，取"到场时最正对"的那块；四块板 90° 均布，任何时刻必有一块到场正对 ≥ 0.707，能持续开火且容差回到 6 cm 级。另加 0.15 的迟滞，避免在两块板交叉点来回换板。
6. **运动估计**：见 5.2。
7. **弹道解算**：见 5.3。
8. **开火判定**：`|gimbal.yaw - yaw_cmd|` 与 `|gimbal.pitch - pitch_cmd|` 均小于随距离收紧的阈值才 `fire=true`，避免未到位时把子弹打飞、拉低命中率。此外还要求：① `motion_ready_`（拟合窗口内样本 ≥ 5）为真——目标在动、而丢失后速度估计还没恢复时，宁可晚 0.1 s 开火，也不打一发没有提前量的空枪（实测这一发必定偏 0.3 m 落地）；② 二次拟合的残差 `fit_rms < 0.025 m`——折返点的窗口里混了减速段和反向加速段，残差会变大，此时速度符号还是"旧的"，外推能偏 0.3 m 以上，直接不发。
9. **灭灯间隙的持续射击**：命中的装甲会灭灯 50 ms 并从发布列表里消失，但仿真 `_collision` 仍然遍历全部四块板做命中判定——灭灯只是"看不见"，不是"打不中"。所以当只剩侧对板时，只要跟踪还是新的（`stamp - last_stamp ≤ hold_grace` = 0.30 s）且拟合可信（`fit_rms < 0.025`），就继续按预测位置跟瞄开火；超过宽限才按手册发 `enable=false / fire=false`（历史仍然保留，回来后立刻接上）。
   列表**整体为空**时另给一个更短的 `hold_grace_empty` = 0.12 s：灭灯最多 50 ms，0.12 s 足够覆盖 3~4 帧，再长多半是目标已被击毁，这时继续开枪只会把子弹算进 `score_fired` 拉低命中率。
   这里有个容易踩的坑：`predictCenter(dt)` 的 `dt` 是相对**最后一次观测**的偏移。正常帧 `last_stamp == stamp`，用 `age` 等价；但 hold 期间不再有观测、`last_stamp` 冻住，若继续用 `age` 推，预测点会停在原地不动，实测会打出一串落点完全相同（`y=0.358` 连打 5 发）的空枪。所以 `aimAndFire` 里统一换算成 `now - last_stamp` 再交给 `solveAim`。

### 5.2 运动估计（`fitMotion` + `updateOmega`）

目标模型取 **装甲中心 = 机器人中心 + r·朝外法向**，即

```
c(t) = p(t) + r · n(t)
```

- **第一步（半径）**：两块板同时可见时，同属一台机器人。设 `u` 为水平方向的单位径向，法向带 15° 安装倾角 `n = cos(15°)·u + sin(15°)·ẑ`，于是 `|Δc_h| = r·|Δu|`、`|Δn_h| = cos(15°)·|Δu|`，故 `r/cos(15°) = |Δc_h| / |Δn_h| ≈ 0.257 m`。**两个坑都在实测里踩过**：① 用三维 `|Δc|` 会把奇数板 `height_difference = 0.1 m` 的高度差算进去，量出 0.267；② 再乘 `cos(15°)` 会得到 0.248，四块板算出的 `q` 会差 1 cm 量级，换板时被当成真实位置跳变（旋转场景判定一度从 0.95 掉到 0.78）。必须只用水平分量，且**不要**再乘 `cos(15°)`——`q = c - r·n` 里沿法向走的长度正好是 `r` 本身。只有一块板可见却在旋转时，用板心切向速度反推 `r = |v| / |ω|`。两种估计都做指数平滑（新值权重 0.15），`r` 变化超过 3 cm 时丢弃旧样本，避免历史整体错位。这比用最小二乘"猜" `r` 更直接，也不会在平移场景退化到 0。
- **第二步（机器人中心）**：历史样本存的是 `q(t) = c(t) - r·n(t)`，即**机器人中心**而不是板心；在 `trans_window`（0.20 s）内对它做二次拟合，得到 `p`、`v`、`a`。这样做的好处是**换板不打断运动估计**——四块板都在以机器人中心为圆心的圆上，换板时 `q` 连续，速度估计不会像按板心记录那样被打断成锯齿（这正是运动靶脱靶的主因）。
- **角速度**：法向水平角 `ψ = atan2(n_y, n_x)` 逐帧解缠（允许 90° 整数倍跳变以兼容四块装甲切换），滑动窗口线性回归得 `ω`；`|ω| < 0.3 rad/s` 判为静止靶。发生跳变时重启片段，避免污染转速。
- **死区与限幅**：`|v| < 0.06 m/s` 置零、`|a| < 0.4 m/s²` 置零，抑制静止靶把角点测量噪声外推成提前量；`|v| ≤ 3 m/s`、`|a| ≤ 4 m/s²`、`r ∈ [0.05, 0.45]` 限幅防发散。
- **速度斜率限制**：二期拟合窗口只有 0.2 s，样本被换板台阶或角点噪声污染时，`v` 会突然从 `+1.0` 翻到 `-0.27`、`a` 抖到 `-2.28`（实测日志）。仿真的平移最高加速度只有 3 m/s²，一帧（20 ms）速度最多变 0.06 m/s，所以给 `v` 加物理斜率限制：突变时按 4 m/s² 逐帧收敛，几帧内就能跟上真实折返。这条把 `v` 的乱跳彻底压住了。
- **换板平移**：同一台车的各块板，水平方向都落在同一个旋转半径上，`q = 板心 - r·法向` 的差别只剩安装高度，是一个**常量**。因此换板时把这个常量整体加到历史样本上（`s.c += Δq`、`p_hat_ += Δq`），速度估计跨板无缝延续，不再清空重来。注意三个分量都要平移：只补 z、把水平残差丢掉，会在历史里留下台阶，二次拟合把台阶读成速度（实测旋转判定从 0.95 掉到 0.67）。
- **折返截断**：仿真的平移动是梯形速度（行程 ±travel，加速度 3 m/s²，到端点先减速停顿再反向加速）。纯二次外推在越过"速度归零"时刻后会继续朝原方向倒飞，因此外推时若 `v·a < 0`（正在减速）且 `t_stop = -v·â/|a| < Δt`，则按梯形模型折返：`q = p + v·t_stop + a·(0.5·t_stop² + 0.5·(Δt-t_stop)²)`。

预测公式：

```
c(t+Δt) = p + v·τ + 0.5·a·τ² + r · Rz(ω·Δt) · n
τ = t + Δt - t_fit
```

### 5.3 弹道解算（`solveAim`）

枪口位置随指令角变化，先按当前解算角把枪口放到

```
muzzle = L · [cos(pitch)cos(yaw), cos(pitch)sin(yaw), sin(pitch)]
```

设目标相对枪口的水平距离 `d`、高度差 `dz`，抛体方程

```
dz = d·tanθ - g·d² / (2·v²·cos²θ)
```

令 `A = g/(2v²)`，化为二次方程 `A·d²·tan²θ - d·tanθ + (dz + A·d²) = 0`，取低伸解

```
tanθ = (1 - sqrt(1 - 4A(dz + A d²))) / (2·A·d)
```

判别式 < 0 时判为超出射程，直接停火。俯仰按机械限位 `[-30°, +20°]` 限幅。

**提前量**：总预测时间

```
Δt = 观测年龄 + 通信/执行延迟(extra_latency) + 开火延迟(delay=15 ms) + 弹丸飞行时间
```

飞行时间用 `t = d / (v·cosθ)`（水平速度恒定，精确），与角度解算迭代 6 次收敛；每轮都用 `Δt` 重新预测目标位置，因此运动靶的提前量、旋转靶的相位、重力下坠由同一套迭代统一处理。

### 7.1 两个评分口径必须讲清楚

**① 命中率不是"命中 / 发射"。** `score_fired` 会把"击毁瞬间仍在飞行"的子弹剔掉，所以每局 `valid_hits` 都是 **18**（350 HP、单发 20 伤害，18 发打爆），命中率实际等于 **18 / score_fired**。这决定了优化的唯一方向是**减少空枪**，而不是提高单发精度——例如 6 m 固定第一轮 18 发全中，所以是 1.0000；4 m 那三轮各多打了 1 发，就只能是 0.9474。

**② `kill_time` 是命中时刻的绝对仿真时间，且只在导出的 JSON 里。** 这一条有个坑：它从 `R` 那一刻归零，但**只统计被仿真接受的指令**。如果指令在头几秒被桥接丢弃（见 7.2），那段时间照样计进 `kill_time`，于是同一份代码会读出 2.1 s 和 6.7 s 两种数字。界面上不显示这个字段，必须导出来看。

### 7.2 本次排查出的最大问题：指令时间戳用错了时钟

前期成绩表里 4 m 固定是 2.94 s、组合是 6.53 s，同一份代码换一次会话就能读出 6.66 s 和 2.11 s 这种差距，原因最终定位到**指令时间戳**：

- 桥接层的准入条件写在 `control_gate.hpp`，其中两条是时间条件：`sim_time - stamp ≤ 0.25`（太旧拒收）、`stamp - sim_time ≤ 0.05`（太新拒收）。
- 我原来把「收到的装甲消息的时间戳」回填进 `AimCommand.header.stamp`。只要那一帧观测稍微过期（或 `R` 重置后缓存里还是上一局的时刻），整条指令就被判为 stale 丢掉，**连同里面的 `fire=true` 一起丢**。
- 节点自己完全无感：日志里照旧打 `fire=1`，仿真那边一发不出。终端 2 会刷 `[aim_sim.bridge]: Rejected stale, out-of-order or invalid command/session`，但那条警告不在节点日志里，所以早期一直没发现。
- 修复：`cmd.header.stamp = this->now()`（当前仿真时间），并用 `use_sim_time:=true` 保证这个时间与 `/clock` 同源。修复后 18 局的首发时刻全部落在 **0.19~0.33 s**，`kill_time` 直接腰斩。

**这条经验值得记下来**：在"指令带时间戳的仿真里"，节点日志显示在发 ≠ 仿真收到了；对不上时要去看桥接侧的拒收日志，而不是继续调算法参数。

### 7.3 已知短板：6 m 平移 + 旋转（0.59）

这是目前唯一的明显短板：单独平移 0.7836、单独旋转 0.8466，两者同时开启掉到 0.5935，平均击毁 5.62 s（其余五项都在 2.1~3.0 s）。三轮都是 31~32 发才打爆 18 发，每局有 8~9 个超过 0.2 s 的开火空档。

已完成定量归因（原始分析脚本与方法见下）：

- **俯仰是准的**：用落点到炮口连线反推弹道，未中弹的竖向偏差均值 +0.015 m，仅 11% 超过 4 cm；落地点的 `x` 呈 ≈7.6 / ≈6.8 两族，正好对应偶/奇板的安装高度 0.26 / 0.16。**偏差全部在横向。**
- **横向偏差 6~8 cm，与"斜擦姿态下的等效容差"同量级**：`0.0675 m × facing`，`facing` 掉到 0.35 时只剩 2.4 cm。
- **开火空档来自折返段**：拟合窗口跨了"减速 + 反向加速"两段，残差升到 0.03~0.06，触发 `tracking_ready=false` 停火；而折返点恰好是速度接近 0、最好打的时刻。曾改成"尾段差商当速度继续开火"，命中率从 0.75 掉到 0.53（差商噪声被 0.3 s 提前量放大），已回退。
- **旋转模式绝不能"锁定就一路打到底"**：旋转靶的到场提前量约 `ω·飞行 ≈ 1.2 rad（70°）`，一块板在整段可见期里，子弹到场时可能已经斜到 60° 以上。曾把"找回锁定板"放在选板之前，结果 `sel` 恒定、56 发 expired、`kill_time=-1`。**旋转模式必须以"到场正对"为唯一判据，锁定只做小范围迟滞。**

**外部参考与已采纳的部分。** 参考了开源队 `sp_vision_25` 的 Auto-Aim 实现（DeepWiki 可查）：它用 11 维 EKF `<px,vx,py,vy,pz,vz,theta,omega,r,dz>` 估计整台车，装甲位置由 `center + Rz(theta)·[r,0,dz]` 解出，换板不需要任何平移历史；弹道用迭代解算（最多 10 次，`|Δt_fly|<0.001` 收敛）。本次落地了两条：**平移拟合窗口 0.20 → 0.30 s**（`v` 的噪声会被 0.3 s 提前量放大，6 m 上 20% 的速度误差就是 6 cm 空枪），以及**选板用"到场时刻的板心"**（`c + v·lead`）而非此刻板心，并把漏掉的**消息年龄**补进到场时间。剩下的 EKF 整车状态估计是结构性重写，本次未做，作为交付后的改进方向。
